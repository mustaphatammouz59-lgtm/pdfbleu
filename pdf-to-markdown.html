Markdown is the plain-text format behind GitHub READMEs, note apps like Obsidian and Notion, documentation sites, and most AI chat tools. Converting a PDF to Markdown turns a fixed, hard-to-reuse document into text you can search, edit, version, quote and feed to other tools — while keeping the structure that makes it readable: headings, lists, tables and links.


This converter works from the PDF itself: it reads each line's font size and weight to spot headings, watches for bullet and number markers to rebuild lists, aligns repeated columns into pipe tables, and turns real PDF link annotations into Markdown links. Embedded images are pulled out into an images folder and referenced from the text, so nothing in the document is silently dropped.









Frequently asked questions


What is Markdown, and where is it used?
Markdown is a lightweight plain-text format: a few simple marks (# for headings, - for lists, ** for bold) give a text file a structure that both people and programs can read. It powers GitHub, documentation sites, note-taking apps such as Obsidian, Joplin and Notion, static site generators — and it is the easiest format to paste into an AI assistant when you want it to work with a document.


How are headings and tables detected?
From the PDF's own signals. A heading is a short line set in a noticeably larger font than the document's body text — the bigger the difference, the higher the heading level. A table is a run of at least three lines whose text starts line up in the same columns, with clear gaps between them. It is a careful heuristic: clean, computer-made documents convert very well, while complex layouts may need a few manual touch-ups afterwards.


Are images included?
Yes. Pictures embedded in the PDF are extracted as PNG files into an images folder and referenced from the Markdown like ![Image p2-1](images/image-p2-1.png). Because the references are relative paths, the download becomes a ZIP containing the .md file and the images folder together. For placement, an image is listed at the end of the page it appears on — a PDF does not record exactly where a picture sits in the reading order, so that is the honest approximation.


What about multi-column documents?
The text is read in the order the PDF itself stores it. Many documents store columns in reading order and convert cleanly, but magazine-style layouts sometimes store a whole page column-crossed — then the Markdown can interleave the columns. There is no reliable way to untangle every such file automatically, and we would rather tell you than pretend otherwise.


My PDF is a scan — what do I do?
A scanned PDF holds pictures of pages, not text, so there is nothing to structure. If your file has almost no text, this page will say so — and if it does contain pictures, it will still extract and reference them. For the text itself, run the file through OCR PDF first to add a recognized text layer, then convert the result here.


Is my file uploaded?
No — everything runs on your device. The file is opened by your browser, its text, links and images are read in this page, and the Markdown is produced locally. Nothing is sent to a server at any point, which is exactly why this tool can be used on private documents with confidence.


How do links work?
Real PDF link annotations — the clickable areas a document carries — become Markdown links, like [documentation](https://example.org/docs), wrapped around the words they covered. Web addresses that are merely written as text, without an annotation behind them, stay as plain text, exactly as written.
