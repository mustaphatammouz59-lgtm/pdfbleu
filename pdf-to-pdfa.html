PDF to PDF/A

PDF/A is the archival form of PDF, standardized as ISO 19005. An ordinary PDF is allowed to borrow fonts from the reader's system and to describe colour in device-dependent terms; a PDF/A file must instead carry everything it needs inside itself — fonts embedded, colour pinned to an output profile, identification metadata included — so that it still renders the same way decades from now.

PDF/A-2b (basic). Based on PDF 1.7. The general-purpose archival level: transparency and modern image compression are allowed, while fonts must be embedded, colour must be device-independent and the file must identify itself. The right default for most archives.
PDF/A-1b (basic). Based on PDF 1.4 — the oldest and strictest level. No transparency, no JPEG 2000 images, no layers. Choose it for maximum compatibility with older archive systems, or when a specification explicitly asks for PDF/A-1.
PDF/A-3b (basic). Everything PDF/A-2b requires, plus the document is allowed to carry other files embedded inside it — a spreadsheet, an XML invoice, source data. Choose it when those attachments are part of the record.

Why are there no “a” or “u” levels here? The a levels (accessible) demand a fully tagged document structure — headings, reading order, alternative text — which only the document's author can supply; a converter cannot invent it, and claiming it could would be false. The u levels additionally demand complete Unicode mappings for every font. If your source PDF is already tagged, converting to PDF/A-2b preserves that structure.

Ticked: when something in the file clashes with the chosen level — a colour the level cannot express, a feature it forbids — the engine reworks that part (converts the colour, drops the feature) and still finishes the conversion. Unticked: the engine stops with an error instead, so you never receive a file that may not conform.

The conversion engine (Ghostscript, running as WebAssembly, about 16 MB) downloads once, the first time you convert — after that, everything runs on your device. Converting large files can take a while on a phone.

⚠️ Honest note: your file is produced by Ghostscript's PDF/A engine — the same open-source engine used by desktop tools. No converter can promise ISO conformance for every possible input, though. If you need certified conformance (a court filing, a government archive), validate the result with veraPDF, the free official PDF/A validator.

Frequently asked questions

What is the difference between PDF and PDF/A?

PDF/A is a restricted profile of PDF (ISO 19005) designed for keeping documents readable far into the future. Anything the page needs must live inside the file: fonts are embedded rather than borrowed from the viewer's system, colour is tied to an output profile instead of a particular device, and features that depend on outside content — external links to missing files, encryption, certain multimedia — are excluded. An ordinary PDF makes no such promises.

Which level should I choose?

For most archives, PDF/A-2b: it is the widely accepted modern level and it tolerates transparency and current image compression. Choose PDF/A-1b when an older system or a written specification demands PDF/A-1 — it is stricter and forbids more, so some modern files cannot meet it. Choose PDF/A-3b when the document carries embedded files (an XML invoice, a spreadsheet) that form part of the record.

Why don't you offer PDF/A-1a or PDF/A-2a?

The “a” stands for accessible, and it requires a fully tagged document: a logical structure of headings, paragraphs and reading order, plus alternative text for images. That structure is authored when the document is created — a converter looking only at the finished pages cannot know which text was a heading, so it cannot honestly produce it. If your source was authored with tags, converting it to PDF/A-2b keeps the structure it already has.

Can I convert a PDF/A file back to a normal PDF?

There is nothing to convert back: a PDF/A file is a normal PDF, and any reader or editor will open it. You can edit it freely — just know that editing can break the conformance (a new font that isn't embedded, for example), after which the file is an ordinary PDF again and would need re-validating, or re-converting, to claim PDF/A.

Is the result certified as conforming?

No converter can certify its own output. This page converts with Ghostscript's PDF/A engine and then runs structural checks on every file — output intent with an embedded ICC profile, the pdfaid identity matching the level you chose, every font embedded, the page count unchanged — and shows you the results. For a formal verdict, run the file through veraPDF, the free validator maintained for the PDF/A standard; that is what archives and courts themselves use.
